KOTE 뉴스 헤드라인 감정 라벨링 플랫폼

화면 흐름 와이어프레임

32만 건 뉴스 헤드라인에서 층화 샘플링한 1,000건을 작업자가 KOTE 44개 감정으로 멀티라벨 라벨링하는 웹앱입니다. 초기에는 Sample 작업자 1명만 만들고, 이후 작업자는 온보딩 화면에서 추가합니다.

전체 흐름

한 건 라벨링의 기본 루프는 ③→④→⑤ 3단계이며, 저장이 서버에서 확인된 후에만 다음 건으로 넘어갑니다.

라벨링 대상 목록 (열람 전용)

  • 1Sample로 즉시 시작 가능.초기 CSV 업로드 시 기본 작업자는 Sample 한 명만 생성. 선택은 브라우저에 저장되어 재방문 시 이어서 작업.
  • 2새 작업자 추가.이름을 입력하면 작업자 문서와 1,000건 배정 큐가 자동 생성. 생성한 브라우저가 해당 이름을 소유.
  • 3라벨링 전 데이터 전수 열람.무엇을 라벨링하는지 시작 전에 확인 — 검색과 버킷 필터 제공.
  • 4버킷 배지로 선정 근거 표시.A=예측 감정별 쿼터 · B=순수 랜덤 · C=모델 저신뢰. 모델의 예측 라벨 자체는 편향 방지를 위해 비공개.

단일 화면에서 판독·선택·저장이 모두 완결

  • 1진행률 상시 표시.137/1000 + 스킵 수 분리 표기.
  • 2헤드라인 크게, 메타(언론사·일시)는 작게.판독 대상에 시선 집중.
  • 3현재 선택 요약.44개 중 무엇을 눌렀는지 한눈에, ✕로 즉시 해제. 미저장 편집은 '미저장 변경' 배지로 구분.
  • 4라벨 검색./ 키 → 타이핑 즉시 필터.
  • 544개 감정 칩 — 긍정/부정/중립 3그룹, 그룹 내 가나다순 고정.모델 예측 기반 정렬·추천은 기본 비활성: anchoring bias로 gold set이 오염되는 것을 방지.
  • 6저장 후 다음 (Enter).서버 저장 성공을 확인한 뒤에만 다음 건으로 이동. 실패 시 재시도 — 데이터 유실 원천 차단.
  • 7스킵은 사유 필수.'판단 불가'와 '감정 없음'을 데이터에서 구분.
  • 8이전/다음 (←/→).지난 건 재수정 허용, 덮어쓰기 저장.

데이터 설계 요점

작업자별 전체 큐 배정

초기 Sample 한 명으로 시작하고, 새 작업자 추가 시 현재 1,000건 전체 큐를 자동 생성. 필요 시 IAA용 중복 라벨링으로 확장.

제시 순서 작업자별 셔플

작업자마다 큐 순서를 분리해 같은 기사라도 서로 다른 작업 시점에 보도록 설계.

건별 즉시 저장 (upsert)

매 건 서버 확인 후 이동. 수정 시 덮어쓰기라 라벨러당 최종 판정이 정확히 1개. annotator·timestamp 기록.

모델 개입 차단 (기본값)

모델 추천·예측순 정렬은 config로만 활성화. 사람의 독립 판정을 확보해 평가용 gold set 오염 방지.
